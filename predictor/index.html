Ya sabes convertir texto en tokens. Un modelo de lenguaje hace con ellos una sola cosa: mira los últimos tokens y calcula qué token es más probable que venga después. Es la misma idea que la red de los dígitos, con otra entrada y otra salida.

Primero verás, paso a paso, cómo da significado a los tokens, cómo decide y cómo aprende. Después lo entrenarás tú y lo usarás para escribir.

01 / QUÉ ES UN EMBEDDING

Darle significado a un número de token.

El tokenizador convierte cada pieza en un número, pero ese número es solo una etiqueta. Antes de decidir nada, la red necesita una forma de saber qué tokens se parecen. Para eso usa los embeddings: una ficha de números para cada token.

06 / GENERAR ES REPETIR

Elegir un token, añadirlo y volver a empezar.

Para generar texto, el modelo predice el siguiente token, se elige uno, se añade al final y se repite. Eso es todo. La temperatura decide cuánto arriesgar: a 0 siempre elige el más probable; más alta reparte las oportunidades entre más opciones.

Gris: lo que has escrito. Color: lo que ha generado el modelo.

Elige tú el siguiente token

Pulsa una barra para añadir ese token. Es el «autocompletar» del teclado del móvil, repetido una y otra vez.

Probable no significa verdadero. El modelo produce lo que encaja con lo que aprendió, aunque sea falso o absurdo. Es lo mismo que pasaba con la superresolución: rellena lo que no sabe con lo que le parece probable. Por eso un chatbot puede «inventarse» un dato con total seguridad.

07 / ¿ES ESTO UN LLM?

Casi todas las piezas ya están aquí.

La red de este capítulo es pequeña y sencilla, pero funciona igual que ChatGPT o Claude en lo esencial. Esto es lo que ya comparte con ellos y lo que le falta.

✓ Lo que ya tiene

  • Tokenizador BPE. Trocea el texto en piezas aprendidas por frecuencia.
  • Embeddings aprendidos. Una ficha de números para cada token.
  • Una probabilidad para cada token. La salida cubre todo el vocabulario.
  • Aprende prediciendo el siguiente token. El propio texto da la respuesta correcta.
  • Genera token a token. Elige, añade y repite, con temperatura.

✗ Lo que le falta

  • Atención. Solo ve 4 tokens en huecos fijos. Un LLM mira todo su contexto y decide qué tokens anteriores importan.
  • La posición como dato. Aquí cada posición tiene su propio hueco; en un LLM la posición se añade a la ficha de cada token.
  • Muchas capas. Aquí hay una capa oculta; un LLM apila decenas de bloques.
  • Escala. 35.588 parámetros y 1.400 frases frente a miles de millones de parámetros y billones de tokens.
  • Aprender a conversar. Tras el preentrenamiento, los asistentes se ajustan con ejemplos de instrucciones y valoraciones de personas para responder como un asistente.

El primer punto de la derecha es el más importante: es lo que hace posible un contexto de cientos de miles de tokens. Es el siguiente capítulo.

LO QUE VIENE

¿Y si el contexto fuera un libro entero?

Nuestra red solo mira los últimos 4 tokens, cada uno en una entrada fija. Un modelo como ChatGPT o Claude es esta misma idea a otra escala: un tokenizador parecido, embeddings, y una red que predice el siguiente token con miles de millones de parámetros. Pero su contexto puede tener cientos de miles de tokens. No sirve tener una entrada fija para cada posición: hace falta un mecanismo que decida a qué tokens anteriores prestar atención. Ese mecanismo se llama atención, y es la base de los transformers.

Lo que le escribes a un chatbot (el prompt) es simplemente el inicio del texto que el modelo tiene que continuar.
